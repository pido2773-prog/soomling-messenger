# Soomling Messenger — сервер

Теперь у мессенджера есть настоящий сервер: аккаунты, сообщения и звонки хранятся не в браузере, а на сервере, так что вы и ваш друг сможете писать и звонить друг другу с разных устройств.

## Что внутри
- `server.js` — Node.js сервер (Express + Socket.io): регистрация/вход, чаты в реальном времени, сигнализация для WebRTC-звонков (аудио/видео), истории.
- `public/index.html` — клиент (уже настроен на работу с этим сервером).
- `package.json` — зависимости.

## Шаг 1. Разверните сервер бесплатно (Render.com)

1. Зайдите на **render.com**, зарегистрируйтесь (можно через GitHub).
2. Загрузите эту папку к себе на GitHub одним репозиторием (создайте новый репозиторий, залейте туда все файлы) — либо просто перетащите папку в GitHub Desktop / через сайт GitHub (кнопка "Add file → Upload files").
3. В Render нажмите **New → Web Service**, подключите этот репозиторий.
4. Настройки:
   - **Build Command:** `npm install`
   - **Start Command:** `npm start`
   - **Plan:** Free
5. Нажмите **Deploy**. Через пару минут Render даст вам ссылку вида `https://soomling-xxxx.onrender.com` — это и есть адрес вашего мессенджера. Откройте его в браузере, зарегистрируйтесь (или войдите под, скиньте ссылку другу — он регистрируется у себя, и вы увидите друг друга по номеру телефона.

Альтернативы Render: **Railway.app** и **Glitch.com** — процесс почти такой же (загрузить репозиторий → Deploy).

## Важно про бесплатный тариф
- На бесплатном плане Render "засыпает" сервис после ~15 минут без запросов — первое открытие после паузы может занять 20–30 секунд, это нормально.
- Файл `db.json` (в нём хранятся все пользователи/сообщения) пересоздаётся при каждом новом деплое на бесплатном тарифе — то есть если вы заново нажмёте "Deploy", данные обнулятся. Для настоящей постоянной базы позже можно подключить бесплатный MongoDB Atlas — скажите, если нужно, помогу переписать хранилище под него.

## Про звонки
Звонки идут напрямую между браузерами (WebRTC), сервер только «знакомит» их (сигнализация) через публичный STUN-сервер Google. Это работает в большинстве случаев (разные Wi-Fi, мобильный интернет), но если у одного из вас очень строгий NAT/файрвол (часто бывает в офисных или мобильных сетях операторов), соединение может не установиться — тогда нужен TURN-сервер. Бесплатный вариант: зарегистрируйтесь на **openrelayproject** (open-source TURN, бесплатно) и добавьте их адреса в `iceServers` в `public/index.html` (в функции `createPC`) — если понадобится, я помогу это настроить.

## Локальный запуск (для проверки на своём компьютере)
```
npm install
npm start
```
Откройте `http://localhost:3000`.
